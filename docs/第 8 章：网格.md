# 网格

## 一、核心主题：多维数据的最近邻搜索（Nearest-Neighbor Search）
本章聚焦**多维数据场景**，核心目标是解决“找最接近目标的数据点”（最近邻搜索）问题，网格（Grids）是实现该目标的关键数据结构——通过空间分区减少搜索范围，优化查询效率，适用于空间（如地图找咖啡店）和非空间（如找相似咖啡）多维数据。

### 1. 最近邻搜索的定义与核心区别
- 定义：给定N个数据点集合、目标点`x'`和距离函数`dist(x,y)`，找到使`dist(x',x_i)`最小的`x_i`（即最接近目标的点）。
- 与二分搜索的差异：二分搜索找“精确匹配”，最近邻搜索找“距离最近的匹配”，支持多维数据和自定义距离函数。
- 核心价值：适配真实场景（如找最近咖啡店、相似天气、近似拼写纠错），只要能定义“距离”即可应用。

### 2. 基础实现：线性扫描（Linear Scan）
- 逻辑：遍历所有数据点，计算每个点与目标的距离，记录最小距离对应的点。
- 代码核心步骤：
  1. 空数组返回`null`，非空则初始化第一个点为候选最近邻。
  2. 循环遍历剩余点，计算当前距离，若小于当前最小距离则更新候选点和最小距离。
  3. 最终返回候选点。
- 优缺点：实现简单、支持任意维度和距离函数，但时间复杂度O(N)，数据量大时效率极低。


## 二、网格（Grids）数据结构——多维数据的空间分区方案
### 1. 定义与核心思想
- 本质：将多维空间（以二维为例）划分为**固定大小的矩形单元格（bin）**，每个单元格存储落在该区域内的所有数据点（用链表存储，支持多个点）。
- 核心思想：利用空间结构“剪枝”——排除距离目标过远的单元格，无需遍历所有数据点，降低搜索成本。
- 类比理解：数组是“鸡蛋盒”（一个格子存一个数据），网格是“冰箱蔬菜抽屉”（一个抽屉存多个同类物品，按空间分区）。

### 2. 网格的结构设计（二维为例）
#### （1）核心属性
```
Grid {
  Integer: num_x_bins  // x轴方向的单元格数量
  Integer: num_y_bins  // y轴方向的单元格数量
  Float: x_start/x_end  // x轴的空间范围（最小值/最大值）
  Float: y_start/y_end  // y轴的空间范围（最小值/最大值）
  Float: x_bin_width    // x方向每个单元格的宽度（预计算：(x_end-x_start)/num_x_bins）
  Float: y_bin_width    // y方向每个单元格的高度（预计算：(y_end-y_start)/num_y_bins）
  Matrix<LinkedList<GridPoint>>: bins  // 单元格矩阵，每个单元格存链表（存储该区域点）
}
```
#### （2）点到单元格的映射逻辑
通过数学计算将数据点的坐标映射到对应的单元格索引：
- `xbin = Floor((x - x_start) / x_bin_width)`
- `ybin = Floor((y - y_start) / y_bin_width)`
- 超出`x_start/x_end`或`y_start/y_end`的点视为“无效”，无法插入网格。

#### （3）数据点结构
每个点存储坐标和链表指针（用于单元格内的点串联）：
```
GridPoint {
  Float: x, y  // 二维坐标
  GridPoint: next  // 指向同一单元格内的下一个点
}
```


### 3. 网格的核心操作
#### （1）插入点（GridInsert）
- 步骤：
  1. 计算点对应的`xbin`和`ybin`，检查是否在有效范围内（无效则返回`False`）。
  2. 新建`GridPoint`，将其插入对应单元格的链表头部（链表操作O(1)）。
  3. 返回`True`表示插入成功。
- 时间复杂度：O(1)（仅计算索引和链表插入，无需遍历其他单元格）。

#### （2）删除点（GridDelete）
- 核心难点：浮点坐标无法直接判等，需用“近似相等”（`approx_equal`函数）——两坐标的差值均小于阈值则视为同一一点。
- 步骤：
  1. 计算点对应的`xbin`和`ybin`，检查有效性和单元格是否为空（空则返回`False`）。
  2. 遍历单元格内的链表，用`approx_equal`找目标点。
  3. 找到后删除该点（修改链表指针），返回`True`；未找到返回`False`。
- 时间复杂度：O(K)（K为目标单元格内的点数，无需遍历其他单元格）。


## 三、网格上的最近邻搜索——优化线性扫描
网格的核心优势是“剪枝无效单元格”，减少需遍历的点数，主要有两种搜索方式：

### 1. 关键前提：单元格剪枝逻辑（Pruning Bins）
- 核心问题：如何判断一个单元格内是否可能存在比当前候选点更近的点？
- 解决方案：计算“目标点到单元格的最小距离”——若该距离≥当前最小距离，则单元格内所有点均无效，可直接跳过。
- 最小距离计算（欧氏距离为例）：
  1. 计算单元格的x/y范围（`x_min=x_start+xbin*x_bin_width`，`x_max=x_min+x_bin_width`；y同理）。
  2. 若目标点在单元格内，最小距离=0；若在外部，最小距离=目标点到单元格边界的直线距离（x方向距离² + y方向距离² 的平方根）。

### 2. 方式1：单元格线性扫描（GridLinearScanNN）
- 逻辑：遍历所有单元格，仅检查“可能存在更近点”的单元格，遍历其内部链表。
- 步骤：
  1. 初始化最小距离为无穷大，候选点为`null`。
  2. 嵌套循环遍历所有`xbin`和`ybin`。
  3. 对每个单元格，计算其最小距离，若小于当前最小距离，则遍历单元格内链表，更新候选点和最小距离。
  4. 返回候选点。
- 优缺点：实现简单，剪枝无效单元格，但仍需遍历所有单元格（空单元格也会被检查），稀疏网格效率低。

### 3. 方式2：扩展搜索（Expanding Search）——最优方案
- 核心思想：从“目标点所在单元格”开始，向外逐层扩展搜索（类似螺旋找钥匙），直到所有可能的单元格都被检查。
- 步骤：
  1. 找到目标点对应的单元格（目标点在网格外则映射到最近单元格）。
  2. 从该单元格开始，按“曼哈顿距离”（网格步数）逐层扩展（0步→1步→2步…）。
  3. 对每个扩展到的单元格，用剪枝逻辑判断是否需要检查，遍历内部链表更新候选点。
  4. 当某一层所有单元格均无效时，停止搜索，返回当前候选点。
- 优缺点：
  - 优点：优先搜索近单元格，找到最优解后可提前终止，效率远高于线性扫描。
  - 缺点：逻辑复杂（需处理扩展顺序、边界检查、终止条件）。


## 四、网格的关键权衡：单元格大小（Bin Size）
单元格大小直接影响搜索效率，需在“单元格内点数”和“单元格数量”之间平衡：
- 单元格过大：每个单元格内点数多，遍历成本高（接近线性扫描）。
- 单元格过小：单元格数量多，空单元格比例高，扩展搜索需遍历大量空单元格，成本高。
- 最优大小：取决于数据量和分布，需根据具体场景调优（如密集数据用小单元格，稀疏数据用大单元格）。


## 五、网格的扩展与局限性
### 1. 高维扩展（Beyond Two Dimensions）
- 逻辑：将二维网格推广到D维，每个维度划分单元格，距离函数扩展为D维欧氏距离（各维度差值平方和的平方根）。
- 核心问题：维度灾难（Curse of Dimensionality）——D维网格需`K^D`个单元格（K为每维单元格数），维度增加时单元格数量爆炸，空单元格比例极高，内存和搜索效率骤降。
- 替代方案：高维数据更适合用k-d树（下一章内容）。

### 2. 非空间数据应用（Beyond Spatial Data）
- 核心思路：将非空间属性视为“维度”，定义合理的距离函数即可应用。
- 示例：找相似咖啡——将“浓度”“酸度”作为二维，用“加权欧氏距离”（如咖啡因权重高于酸度）计算相似度。
- 关键注意：距离函数需包含所有关注维度（如忽略“是否脱咖啡因”可能导致搜索结果不符合需求）。


## 六、核心总结与价值
### 1. 网格的核心价值
- 解决多维数据的最近邻搜索：通过空间分区剪枝无效数据，效率远超线性扫描。
- 灵活适配：支持任意距离函数（欧氏、曼哈顿、加权等），空间和非空间数据均适用。
- 操作高效：插入、删除仅涉及单个单元格，时间复杂度与整体数据量无关。

### 2. 局限性
- 单元格大小难调优：需根据数据分布手动调整，无通用最优解。
- 维度灾难：高维数据（D>3）中单元格数量爆炸，不适用。
- 静态结构：网格的空间范围和单元格数量固定，无法动态适配数据变化。

### 3. 后续衔接
网格是“空间分区”的基础，下一章将结合“树的动态适应性”，介绍更适合高维数据的k-d树，解决网格的局限性。

### 4. 关键对比（网格 vs 线性扫描）
| 对比维度         | 线性扫描（Linear Scan）      | 网格扩展搜索（Expanding Search） |
|------------------|-----------------------------|---------------------------------|
| 时间复杂度       | O(N)（N为总点数）            | O(K)（K为需检查的点数，K<<N）   |
| 适用场景         | 数据量小、低维数据           | 中低维数据、数据分布较密集      |
| 核心优势         | 实现简单、无需预处理         | 剪枝无效数据、效率高            |
| 核心劣势         | 数据量大时效率极低           | 需预处理建网格、高维数据不适用  |
