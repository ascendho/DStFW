# B树

## 一、核心定义与本质
### 1. 基础信息
- 发明背景：由计算机科学家Rudolf Bayer和Edward McCreight设计，是一种**自平衡的多叉树数据结构**。
- 核心目标：优化“块存储”场景下的访问成本（如硬盘、网络服务器），通过“单个节点存储多个键”减少块检索次数，同时保证树的平衡，避免性能退化。
- 核心特性：
  - 多键多子节点：每个节点存储多个有序键，对应更多子节点，减少树的深度；
  - 自平衡：所有叶节点位于同一深度，插入/删除时通过分裂、合并节点维持平衡；
  - 节点容量约束：非根节点的键数在`k~2k`之间（k为节点大小参数），根节点键数可在`0~2k`之间。

### 2. 核心用途
- 大规模数据索引：适用于数据库索引、文件系统（如NTFS、Ext4）等场景，需频繁从块存储中读取数据；
- 减少IO开销：单个节点对应一个存储块，一次块读取可获取多个键，降低“块检索”的昂贵开销。


## 二、结构设计
### 1. 核心数据结构定义（伪代码）
#### （1）B树本身（BTree）
```
BTree {
  BTreeNode: root    // 根节点
  Integer: k         // 节点大小参数，决定非根节点的键数范围（k~2k）
}
```

#### （2）B树节点（BTreeNode）
```
BTreeNode {
  Integer: k         // 与B树的k一致
  Integer: size      // 当前节点存储的键数
  Boolean: is_leaf   // 是否为叶节点（叶节点无子节点）
  Array of Type: keys       // 存储有序键的数组
  Array of BTreeNodes: children  // 子节点指针数组（长度=size+1）
}
```

### 2. 节点键与子节点的映射规则
- 子节点`children[i]`中的所有键，均小于`keys[i]`且大于`keys[i-1]`（`i>0`时）；
- 例如：节点键为[12,31,45]时，对应4个子节点，分别存储“<12”“12~31”“31~45”“>45”的键。

### 3. 结构关键约束
| 节点类型 | 键数范围 | 子节点数范围 | 说明 |
|----------|----------|--------------|------|
| 根节点   | 0~2k     | 0~2k+1       | 允许为空（空树），或仅有1个键+2个子节点 |
| 非根节点 | k~2k     | k+1~2k+1     | 保证至少半满，避免节点冗余；子节点数=键数+1 |


## 三、核心操作（伪代码逻辑+步骤）
B树的所有操作均围绕“维持节点容量约束”和“树平衡”展开，核心流程为“从根到叶遍历操作，回溯时修复节点”。

### 1. 搜索操作（BTreeSearch）
#### （1）核心逻辑
从根节点开始，扫描当前节点的有序键，找到目标键所在的子节点范围，递归向下遍历，直至叶节点；若叶节点未找到则返回null。

#### （2）伪代码关键步骤
```
输入：B树tree、目标键target
输出：目标键（不存在则返回null）
1. 递归函数BTreeNodeSearch(node, target)：
   a. 初始化i=0，线性扫描节点的keys数组：
      - 若target >= keys[i]，i自增；
      - 若target == keys[i]，返回该键；
   b. 若当前节点是叶节点，返回null；
   c. 否则递归遍历子节点children[i]，重复步骤a~c。
2. 调用BTreeNodeSearch(tree.root, target)，返回结果。
```

#### （3）优化点
- 节点内键的扫描可替换为**二分查找**，将节点内查找时间从O(n)降至O(log n)，整体效率更高。

### 2. 插入操作（BTreeInsert）
#### （1）核心挑战
需保证插入后节点键数不超过`2k`（避免溢出），且树仍平衡。核心策略：“插入到叶节点→回溯时分裂溢出节点”。

#### （2）关键辅助函数
- `BTreeNodeAddKey(node, key, next_child)`：向非满节点插入键和对应子节点（叶节点忽略next_child），通过数组移位腾出空间。
- `BTreeNodeIsOverFull(node)`：判断节点是否溢出（键数==2k+1）。
- `BTreeNodeSplit(node, child_index)`：分裂溢出子节点：
  1. 取溢出子节点的中间键（split_key）；
  2. 中间键插入父节点，溢出子节点分裂为“左子节点（存前半键）”和“右子节点（存后半键）”；
  3. 父节点的子节点指针更新为“左子节点→右子节点”。

#### （3）插入主流程伪代码
```
输入：B树tree、待插入键key
1. 调用递归函数BTreeNodeInsert(tree.root, key)：
   a. 扫描当前节点keys，找到插入位置i；
   b. 若当前节点是叶节点，调用BTreeNodeAddKey插入键；
   c. 若当前节点是内部节点，递归插入到子节点children[i]；
   d. 插入后检查子节点是否溢出，若溢出则调用BTreeNodeSplit分裂。
2. 若根节点溢出，创建新根节点，将原根节点作为新根的子节点，分裂原根节点（树高+1）。
```

#### （4）示例流程
- 插入非溢出叶节点：直接移位插入键，无需分裂；
- 插入溢出叶节点：分裂叶节点，中间键晋升至父节点；
- 父节点溢出：分裂父节点，中间键继续晋升，直至根节点（必要时树高增加）。

### 3. 删除操作（BTreeDelete）
#### （1）核心挑战
需保证删除后节点键数不低于`k`（避免下溢），且树仍平衡。核心策略：“删除键→回溯时修复下溢节点”。

#### （2）关键辅助函数
- `BTreeNodeIsUnderFull(node)`：判断节点是否下溢（键数<k）。
- `BTreeNodeMerge(node, index)`：合并下溢节点与其相邻 sibling 节点：
  1. 取父节点中分隔两个 sibling 的键；
  2. 将分隔键、右 sibling 的所有键合并到左 sibling 中；
  3. 删除父节点的分隔键和右 sibling 指针。
- `BTreeNodeTransferLeft/Right(node, index)`：从 sibling 节点转移一个键到下溢节点：
  1. 父节点的分隔键下移至下溢节点；
  2. sibling 节点的一个键上移至父节点，维持键的有序性。
- `BTreeNodeFindMin(node)`：查找节点子树中的最小键（用于内部节点删除后替换）。

#### （3）删除主流程伪代码
```
输入：B树tree、待删除键key
1. 调用递归函数BTreeNodeDelete(tree.root, key)：
   a. 扫描当前节点keys，找到键的位置i；
   b. 若当前节点是叶节点：找到键则删除（数组移位），否则返回；
   c. 若当前节点是内部节点：
      - 找到键则用子树最小键（BTreeNodeFindMin(children[i+1])）替换，删除该最小键；
      - 未找到键则递归删除子节点children[i]；
   d. 删除后检查子节点是否下溢，若下溢则调用BTreeNodeRepairUnderFull修复（合并或转移键）。
2. 若根节点键数为0且非叶节点，将根节点替换为其唯一子节点（树高-1）。
```

#### （4）修复下溢节点的逻辑
- 若下溢节点与 sibling 合并后的键数<2k：执行合并操作；
- 否则：从键数更多的 sibling 转移一个键，避免合并。


## 四、时间复杂度与核心优势
### 1. 时间复杂度
| 操作         | 时间复杂度 | 说明 |
|--------------|------------|------|
| 搜索（Search）| O(logₖN)   | 树高为logₖN，k为非根节点的最小子节点数（k+1） |
| 插入（Insert）| O(logₖN)   | 遍历+回溯分裂，最多分裂logₖN个节点 |
| 删除（Delete）| O(logₖN)   | 遍历+回溯修复，最多合并logₖN个节点 |

### 2. 核心优势
- 低IO开销：单个节点对应一个存储块，一次块读取可获取多个键，减少块检索次数；
- 自平衡保证：所有叶节点同深度，避免二叉搜索树“有序插入退化链表”的问题；
- 通用性强：支持任意可排序键，适用于数据库、文件系统等多种大规模存储场景。

### 3. 与其他平衡树的对比
| 数据结构   | 核心差异 | 适用场景 |
|------------|----------|----------|
| B树        | 多键多子节点，优化块存储 | 数据库索引、文件系统（块存储） |
| 红黑树     | 二叉树，单键双子节点 | 内存中的有序数据操作（如Java TreeMap） |
| 跳表       | 随机化结构，链表+多层指针 | 内存中的高效查找（如Redis有序集合） |


## 五、关键要点与实际应用
### 1. 关键要点
- 节点容量约束：非根节点“半满”（k个键）是平衡的基础，避免节点冗余和树深度过大；
- 分裂与合并：插入仅通过分裂节点扩展树，删除仅通过合并/转移修复下溢，保证平衡；
- 键的有序性：节点内键始终有序，支持二分查找，提升节点内检索效率；
- 树高变化：仅根节点分裂/合并会改变树高，所有叶节点深度同步更新，维持平衡。

### 2. 实际应用场景
- 数据库索引：MySQL、Oracle等关系型数据库的索引核心（如InnoDB的聚集索引）；
- 文件系统：NTFS、Ext4、XFS等文件系统的目录结构索引；
- 分布式存储：HBase、MongoDB等分布式数据库的底层索引，适配远程块存储访问。


## 六、核心价值总结
B树的核心价值在于“适配块存储的效率优化”与“自平衡的稳定性”：
1. 通过“多键单节点”减少块检索次数，解决块存储IO昂贵的问题；
2. 通过分裂、合并、键转移等操作，强制维持树的平衡，保证搜索、插入、删除的稳定高效；
3. 通用性强，无需依赖数据分布，适用于任意可排序键的大规模数据场景，是工程中“平衡树+块存储”的经典解决方案。
