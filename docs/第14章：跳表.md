# 跳表

## 一、核心定义与本质
### 1. 基础信息
- 发明背景：由计算机科学家William Pugh提出，是一种**排序链表的优化结构**，核心解决普通链表“逐节点扫描”的低效问题。
- 核心目标：通过“多层指针跳跃”机制，让搜索、插入、删除操作的平均效率大幅提升，成为平衡搜索树的简化替代方案。
- 本质特性：
  - 有序性：底层是排序链表，所有节点按key有序排列；
  - 多层结构：每个节点包含多个指针，对应不同“层级”，高层指针可跳过多个低层节点；
  - 随机化：节点的层级（高度）由随机算法决定，而非由插入数据的顺序决定，以此避免最坏情况，保证平均性能稳定。

### 2. 随机化vs确定性数据结构
| 类型         | 特点（以跳表为例）                                                                 | 对比（传统结构如BST、哈希表）                     |
|--------------|----------------------------------------------------------------------------------|--------------------------------------------------|
| 随机化结构   | 数据结构的结构由“数据+随机参数”共同决定（如节点层级随机选择）；避免持续的次优选择，平均性能稳定。 | 结构完全由插入数据的顺序决定；易因最坏情况数据（如有序数据插入BST）导致性能退化。 |
| 核心优势     | 无需复杂的平衡维护（如BST的旋转），实现简单，且平均性能与平衡树相当。               | 精确结构可预测，但需额外逻辑处理最坏情况，实现复杂。 |

### 3. 核心用途
- 有序数据的高效操作：适用于需要频繁执行“搜索、插入、删除”的有序数据集（如有序键值对存储、缓存系统）；
- 平衡树的替代方案：在平均性能不逊色于红黑树、AVL树的前提下，大幅降低实现复杂度。


## 二、结构设计
### 1. 整体架构
跳表的核心是“多层链表层级结构”，高层链表是低层链表的“稀疏采样”（高层节点更少，跳跃距离更远），形成“从粗到细”的搜索路径：
- 高层：节点稀疏，指针跳跃距离长，用于快速缩小搜索范围；
- 低层：节点密集，指针跳跃距离短，用于精确定位目标；
- 最底层：包含所有节点的完整排序链表，保证数据的完整性。

### 2. 核心数据结构定义
#### （1）跳表本身（SkipList）
```
SkipList {
  SkipListNode: front    // 哨兵节点（无key/value，存储各层链表头指针）
  Integer: top_level     // 当前跳表的最高有效层级
  Integer: max_level     // 允许的最大层级（预定义，避免指针数组越界）
}
```
- 哨兵节点`front`：简化插入/删除的边界处理（无需判断“链表头部”情况），其`next`数组覆盖所有层级。

#### （2）跳表节点（SkipListNode）
```
SkipListNode {
  Type: key              // 节点键（有序排列）
  Type: value            // 节点值
  Integer: height        // 节点的层级（高度）
  Array of SkipListNodes: next  // 各层级的下一个节点指针（索引0=最底层，索引=height=最高层）
}
```
- 关键特性：层级为`L`的节点，会出现在第`0`到`L`层的所有链表中，即`next`数组长度为`L+1`。


## 三、核心操作（伪代码逻辑+步骤）
跳表的所有操作均遵循“从高层到低层”的遍历逻辑：先通过高层指针快速缩小范围，再到低层精确定位。

### 1. 搜索操作（SkipListSearch）
#### （1）核心逻辑
从最高层开始，优先沿当前层向右遍历（跳过小于目标的节点）；若无法继续（下一个节点为null或key≥目标），则降一层继续；直至最底层后，检查下一个节点是否为目标。

#### （2）伪代码关键步骤
```
输入：跳表list、目标key
输出：目标value（不存在则返回null）
1. 初始化：level = list.top_level，current = list.front（从哨兵节点最高层开始）
2. 外层循环（降层）：while level ≥ 0：
   a. 内层循环（当前层向右遍历）：while current.next[level] != null 且 current.next[level].key < 目标：
       current = current.next[level]  // 沿当前层跳跃
   b. level = level - 1  // 降一层
3. 检查结果：result = current.next[0]（最底层的下一个节点）
   a. 若result存在且result.key == 目标：返回result.value
   b. 否则：返回null
```

#### （3）示例
- 搜索key=14：从最高层（如3层）向右跳至key=13（小于14），因无更高层节点而降层；逐层降至上底层后，current.next[0]即为key=14。
- 搜索key=12：高层快速缩小范围后，提前降至上底层，沿底层链表遍历至目标。

### 2. 插入操作（SkipListInsert）
#### （1）核心逻辑
先执行“搜索类似流程”，记录每一层中“最后一个key小于目标”的节点（`last`数组）；再随机生成新节点的层级；最后更新`last`数组中各层节点的指针，将新节点插入跳表。

#### （2）伪代码关键步骤
```
输入：跳表list、待插入key、value
1. 初始化：level = list.top_level，current = list.front，last数组（大小=list.max_level+1，初始值=front）
2. 遍历并记录last数组（同搜索的降层+向右遍历逻辑）：
   a. 内层循环向右遍历，直至无法继续；
   b. 记录当前层的last[level] = current；
   c. 降层继续，直至level < 0。
3. 检查重复：若current.next[0]存在且key==目标，直接更新value并返回（键唯一）。
4. 生成新节点层级：new_level = 随机选择层级（按概率分布）。
5. 调整跳表最高层：若new_level > list.top_level，更新list.top_level = new_level。
6. 创建新节点：new_node = SkipListNode(key, value, new_level)。
7. 链接新节点：for j from 0 to new_level：
   a. new_node.next[j] = last[j].next[j]  // 新节点指向原后续节点
   b. last[j].next[j] = new_node          // 原前驱节点指向新节点
```

#### （3）关键细节
- `last`数组：存储各层中“新节点的前驱节点”，确保插入时能同步更新所有涉及层级的指针。

### 3. 删除操作（SkipListDelete）
#### （1）核心逻辑
与插入类似：先搜索目标节点并记录`last`数组；若找到目标节点，更新`last`数组各层指针，跳过目标节点；最后调整跳表的最高层（若删除的是最高层唯一节点）。

#### （2）伪代码关键步骤
```
输入：跳表list、待删除key
1. 初始化：level = list.top_level，current = list.front，last数组（初始值=front）
2. 遍历并记录last数组（同搜索逻辑）。
3. 检查目标：result = current.next[0]，若result不存在或key≠目标，直接返回（无此节点）。
4. 移除目标节点：for j from 0 to result.height：
   a. last[j].next[j] = result.next[j]  // 前驱节点跳过目标节点
   b. result.next[j] = null             // 释放目标节点指针
5. 调整最高层：若result.height == list.top_level：
   a. 从top_level向下遍历，找到第一个front.next[top]≠null的层级；
   b. 更新list.top_level = 该层级（避免最高层为空）。
```


## 四、节点层级选择策略（随机化核心）
节点层级的随机选择直接决定跳表的结构和性能，采用“概率晋升”机制：
### 1. 规则
- 所有节点初始层级为0（最底层）；
- 每次以固定概率`p`（推荐`p=0.5`）决定是否“晋升层级”：
  - 生成0~1的随机数，若小于`p`，层级+1；
  - 重复此过程，直至随机数≥`p`或层级达到`max_level`；
- 最终层级即为节点的`height`。

### 2. 目的
- 保证层级分布稀疏：层级`L+1`的节点数约为层级`L`的`p`倍（如`p=0.5`时，每升一层节点数减半）；
- 形成“高层少、低层多”的合理结构，确保跳跃机制有效（高层跳大步，低层精确定位）。

### 3. 示例（p=0.5）
- 层级0：所有节点（100%）；
- 层级1：约50%的节点；
- 层级2：约25%的节点；
- 层级k：约`(0.5)^k`的节点。


## 五、时间复杂度分析
| 操作         | 最好情况 | 最坏情况 | 平均情况（p=0.5时） | 说明                                  |
|--------------|----------|----------|---------------------|---------------------------------------|
| 搜索（Search）| O(log n) | O(n)     | O(log n)            | 最好：类似二分查找，每层跳过一半节点；最坏：所有节点层级为0，退化为普通链表。 |
| 插入（Insert）| O(log n) | O(n)     | O(log n)            | 主要开销为“遍历找插入位置”和“更新指针”，均与层级数相关。 |
| 删除（Delete）| O(log n) | O(n)     | O(log n)            | 与插入逻辑类似，开销集中在遍历和指针更新。 |

- 关键前提：平均情况的O(log n)依赖“合理的层级分布”（即`p`和`max_level`参数配置得当）。


## 六、与其他数据结构对比
### 1. 跳表 vs 普通排序链表
| 特性         | 跳表                | 普通排序链表        |
|--------------|---------------------|---------------------|
| 搜索效率     | 平均O(log n)        | O(n)                |
| 插入/删除效率 | 平均O(log n)        | O(n)                |
| 额外开销     | 存储多层指针（内存） | 无                  |
| 核心优势     | 解决“逐节点扫描”低效 | 实现简单、内存占用低 |

### 2. 跳表 vs 平衡二叉树（红黑树/AVL树）
| 特性         | 跳表                | 平衡二叉树          |
|--------------|---------------------|---------------------|
| 平均性能     | O(log n)            | O(log n)            |
| 最坏情况     | O(n)（概率极低）    | O(log n)（强制平衡） |
| 实现复杂度   | 低（无旋转等平衡操作）| 高（需维护平衡规则） |
| 有序操作支持 | 天然支持（底层排序） | 支持但需中序遍历    |
| 随机访问     | 不支持              | 不支持              |

- 核心结论：跳表以“极低的实现复杂度”换取“与平衡树相当的平均性能”，是工程中更易维护的选择。


## 七、核心价值与关键要点
### 1. 核心价值
- 简化性：无需像平衡树那样维护复杂的平衡规则（如红黑树的颜色翻转、旋转），插入/删除逻辑直观，代码易实现、易调试；
- 稳定性：通过随机化层级选择，避免因“有序数据插入”等最坏情况导致的性能退化，平均性能稳定；
- 高效性：解决了普通链表的低效问题，同时保留了链表“动态插入/删除无需移动大量元素”的优势；
- 灵活性：层级结构可通过`p`和`max_level`参数调整，适配不同场景（如内存紧张时可减小`p`，减少指针开销）。

### 2. 关键要点
- 哨兵节点`front`：是跳表实现简化的核心，统一了“头部插入”和“中间插入”的逻辑；
- `top_level` vs `max_level`：`top_level`是当前有效最高层（随插入/删除动态变化），`max_level`是预定义的最大限制（避免指针数组无限扩展）；
- 无假阳性/假阴性：与布隆过滤器不同，跳表的操作结果是精确的（不存在概率性错误），随机化仅影响结构而非结果正确性。
