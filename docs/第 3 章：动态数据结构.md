# 动态数据结构

## 一、核心概念：静态与动态数据结构的本质区别
### 1. 定义与核心差异
- 静态数据结构（如数组）：创建时**大小和内存布局固定**，仅能修改内部数据，无法动态调整结构（扩容、缩容、灵活插入/删除）。
- 动态数据结构（如链表）：可随数据变化**动态调整结构**，包括按需扩容、通过指针建立可变链接、灵活插入/删除元素，无需依赖固定内存块。
- 核心价值：解决静态结构的刚性限制，适配程序运行时的数据动态变化（如分数榜新增高分、文档动态输入字符等）。

### 2. 类比理解
- 静态数组 ≈ 固定车位的停车场：只能在现有车位上停放/移动车辆，无法新增车位。
- 动态链表 ≈ 可伸缩的排队人群：无需固定空间，能随时在队首、队尾或中间插入/移除人员，仅需调整前后位置关系。


## 二、静态数组（Array）的局限性
数组是基础静态数据结构，核心问题源于“创建时固定大小”，具体局限如下：
### 1. 无法动态扩容
- 问题：若存储数据超出数组容量，需新建更大数组，复制原数组所有元素到新数组，再添加新数据，开销巨大（O(N)时间复杂度）。
- 示例：游戏高分榜用5元素数组存储分数，新增更高分时无法直接添加，需重建数组。
- 妥协方案：数组加倍（Array Doubling）策略
  - 逻辑：数组满时，新建容量为原2倍的数组，复制原数据。
  - 代码：`ArrayDouble(Array: old_array)` → 分配2倍大小新数组，循环复制原元素。
  - 权衡：平衡扩容频率（数组越大，扩容越罕见）与内存浪费（最多浪费不到一半空间）。

### 2. 中间插入/删除元素开销大
- 中间插入：需将目标位置后的所有元素**逐个后移**（最坏O(N)），若数组已满，还需先扩容（额外O(N)复制成本）。
- 中间删除：需将目标位置后的所有元素**逐个前移**（最坏O(N)），填补内存间隙。
- 示例：在10000元素数组的第2位插入元素，需移动9999个元素。

### 3. 存储动态大小数据受限
- 问题：数组每个元素的内存空间固定，无法直接存储变长数据（如不同长度的字符串、复合结构）。
- 浪费：若为适配最长数据预留空间，短数据会占用冗余内存（如预留1000字符存储“John Smith”）。


## 三、指针与引用（Pointers and References）—— 动态结构的核心
### 1. 定义与本质
- 指针：存储**内存地址**的变量，本身不存数据，仅指向数据所在的内存位置（类似“文件存放地址纸条”）。
- 核心作用：打破内存块的连续性限制，实现跨内存块的链接，是动态数据结构的基础。
- 关键特性：
  - 空值（Null/None）：表示指针未指向有效内存（暂无对应数据）。
  - 语言差异：C/C++提供原始指针（直接操作内存地址），Python/Java用“引用”（语法简化，隐藏底层内存操作）。
  - 统一术语：本书中“指针”泛指所有用于链接内存块的变量（指针、引用、索引）。

### 2. 实际意义
- 避免数据复制：共享同一数据时，仅传递指针（地址），无需复制庞大的原始数据（如团队共享文件夹，仅传递存放地址）。
- 支持动态链接：通过修改指针指向的地址，可灵活调整数据结构的链接关系（如链表插入/删除）。


## 四、链表（Linked Lists）—— 基础动态数据结构
### 1. 定义与结构
- 本质：由**节点（Node）** 通过指针串联而成的线性结构，无需连续内存块。
- 节点结构（单链表）：
  ```
  LinkedListNode {
    Type: value  // 存储数据
    LinkedListNode: next  // 指向后一个节点的指针
  }
  ```
- 链表标识：通过“头指针（head）”指向第一个节点，尾节点的`next`指针为Null（标识链表结束）。
- 存储特点：节点分散在内存中，仅通过`next`指针维持逻辑顺序（物理上无需相邻）。

### 2. 核心操作（单链表）
#### （1）查找（LinkedListLookUp）
- 目标：根据索引查找节点。
- 步骤：
  1. 从`head`出发，用`current`指针追踪当前节点，`count`记录索引。
  2. 循环遍历：`current = current.next`，`count++`，直到`count == 目标索引`或`current == Null`（索引无效）。
- 时间复杂度：O(N)（需从头遍历，无直接索引访问）。

#### （2）插入（LinkedListInsert）
- 核心原则：仅需修改指针，无需移动节点（区别于数组的元素移位）。
- 三种场景：
  1. 插入表头（索引0）：
     - 新建节点，其`next`指向原`head`，更新`head`为新节点。
     - 时间复杂度：O(1)。
  2. 插入表尾：
     - 遍历至尾节点（`next == Null`），将尾节点`next`指向新节点，新节点`next = Null`。
     - 时间复杂度：O(N)（需遍历至尾部）。
  3. 插入中间（索引i）：
     - 步骤：① 找到目标位置的前一个节点`previous`；② 新节点`next = previous.next`；③ `previous.next = 新节点`。
     - 关键：先链接新节点与后一个节点，再断开前节点与后节点的链接（避免丢失后节点地址）。
     - 时间复杂度：O(N)（遍历查找`previous`节点）。
- 代码逻辑：处理表头特殊情况→遍历找位置→验证索引有效性→修改指针完成插入。

#### （3）删除（LinkedListDelete）
- 核心原则：断开待删节点的指针链接，释放其内存（或标记为无效）。
- 三种场景：
  1. 删除表头（索引0）：
     - 新`head = 原head.next`，原表头`next = Null`（避免悬空指针）。
     - 时间复杂度：O(1)。
  2. 删除表尾：
     - 遍历至倒数第二个节点，将其`next = Null`。
     - 时间复杂度：O(N)。
  3. 删除中间（索引i）：
     - 步骤：① 找到`previous`节点和待删节点`current`；② `previous.next = current.next`；③ `current.next = Null`。
     - 时间复杂度：O(N)（遍历查找`previous`和`current`）。
- 边界处理：空链表直接返回Null；索引超出范围返回错误。

### 3. 链表与数组的核心对比
| 对比维度         | 数组（静态）                | 单链表（动态）              |
|------------------|-----------------------------|-----------------------------|
| 内存布局         | 连续内存块                  | 分散内存块（指针链接）      |
| 访问元素         | 直接索引访问（O(1)）        | 从头遍历（O(N)）            |
| 插入/删除（中间） | 元素移位（O(N)）            | 指针修改（O(N)遍历+O(1)修改）|
| 插入/删除（表头） | 元素移位（O(N)）            | 指针修改（O(1)）            |
| 扩容             | 新建数组+复制（O(N)）       | 直接新增节点（O(1)或O(N)）  |
| 内存开销         | 无额外开销（仅存数据）      | 额外存储指针（K×M字节，M为指针大小）|
| 存储变长数据     | 需指针间接存储（数组存指针）| 节点可直接指向变长数据      |


## 五、链表的扩展：双向链表（Doubly Linked Lists）
### 1. 定义与结构
- 节点结构：在单链表基础上增加“前驱指针（previous）”，支持双向遍历：
  ```
  DoublyLinkedListNode {
    Type: value
    DoublyLinkedListNode: next  // 后驱指针
    DoublyLinkedListNode: previous  // 前驱指针
  }
  ```
- 优势：
  - 可双向遍历（向前/向后访问节点）。
  - 删除已知节点时，无需遍历查找`previous`（直接通过`node.previous`获取），效率优化。

### 2. 操作特点
- 插入/删除：需同时维护`next`和`previous`两个指针（如插入节点N在X和Y之间：`N.next=Y`、`N.previous=X`、`X.next=N`、`Y.previous=N`）。
- 复杂度：查找仍为O(N)，但特定场景（如已知节点删除）可简化为O(1)。


## 六、数组与链表的结合：存储复杂/变长数据
### 1. 核心思路
- 数组存储指针：数组的每个元素为指针，指向内存中分散的复杂数据（如字符串、复合结构），解决数组“固定元素大小”的限制。
- 示例：RSVP列表（数组存指针，每个指针指向包含“姓名、音乐偏好”的复合结构）。
- 链表节点存储指针：链表节点的`value`可改为指针，指向变长数据（如大字符串、动态数组），兼顾链表的灵活性和数据的动态性。

### 2. 优势
- 数组：维持直接访问的特性（O(1)访问指针），指针大小固定，无内存浪费。
- 链表：维持插入/删除的灵活性，节点仅存指针，数据本身可动态扩容。


## 七、核心权衡与重要性
### 1. 数据结构的本质：trade-off（权衡）
| 选择依据         | 优先选数组                  | 优先选链表                  |
|------------------|-----------------------------|-----------------------------|
| 操作频率         | 频繁随机访问（查多改少）    | 频繁插入/删除（改多查少）    |
| 数据特性         | 数据量固定、长度一致        | 数据量动态、长度可变        |
| 性能需求         | 追求访问速度（O(1)）        | 追求修改灵活性（O(1)修改）  |

### 2. 动态数据结构的核心价值
- 指针是关键：通过存储内存地址，打破连续内存的限制，实现数据结构的动态调整。
- 为高级结构奠基：链表是栈、队列、二叉树等复杂动态数据结构的基础，后续章节将基于链表扩展。
- 适配真实场景：绝大多数程序需处理动态数据（如用户输入、网络请求、数据更新），动态结构是实现高效算法的前提。


## 八、关键总结
1. 静态数组的核心痛点是“固定大小”，导致扩容、插入/删除开销大；动态链表通过指针解决此问题，代价是牺牲直接访问能力。
2. 指针/引用是动态结构的灵魂，其核心作用是“链接内存块”，避免数据复制，支持灵活调整。
3. 链表的优势在“修改操作”（插入/删除），数组的优势在“访问操作”（随机访问），需根据场景选择。
4. 双向链表、数组+指针的组合，是对基础结构的优化，适配更复杂的使用场景（如双向遍历、变长数据存储）。
