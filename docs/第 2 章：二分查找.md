# 二分查找

## 一、核心定义与意义
### 1. 算法本质

二分查找是针对**有序列表**的高效搜索算法，核心逻辑是：通过反复将搜索范围二分，判断目标值可能存在的子区间，丢弃无关子区间，逐步缩小范围直至找到目标或确认其不存在。

### 2. 核心价值
- 不仅是一种可直接实现的搜索工具，更核心的是展示了**数据结构与算法的深度交互**——利用数据的有序结构（简单却关键的结构）实现计算效率的巨大提升。
- 逻辑简洁、易分析正确性与效率，是计算机科学入门的核心主题，几乎贯穿所有CS课程与教材。


## 二、搜索问题定义
- **形式化描述**：给定含N个数据点的集合 \(X=\{x_1, x_2, ..., x_N\}\) 和目标值 \(x'\)，找到 \(x_i \in X\) 使得 \(x'=x_i\)，或提示无此元素。
- **日常场景**：字典查词、联系人列表找名字、超市找特定品牌商品、历史事件按日期查询等，核心是“从候选集合中匹配目标”。


## 三、对比基准：线性查找（Linear Scan）
### 1. 算法原理
逐个遍历列表中的每个元素，与目标值逐一对比，直到找到匹配项或遍历结束。

### 2. 代码实现（伪代码）
```python
LinearScan(Array: A, Integer: target):
    Integer: i = 0
    WHILE i < length(A):
        IF A[i] == target:
            return i  # 找到目标，返回索引
        i = i + 1
    return -1  # 未找到，返回-1
```

### 3. 特点
- **优势**：暴力可靠，无需数据预处理（无序也可），必能找到目标（若存在）。
- **劣势**：低效，尤其是大数据集。最坏情况需遍历所有N个元素（目标在末尾或不存在），无法利用数据结构优化。
- **优化局限**：仅能提升单次比较速度（如字符串比较时提前终止不匹配字符），但无法改变“逐个检查”的本质。


## 四、二分查找核心算法
### 1. 前提条件
数据必须有序（支持递增或递减排序，以下以**递增排序**为例），即对任意索引 \(i<j\)，满足 \(A[i] \leq A[j]\)。

### 2. 核心逻辑
通过两个边界跟踪**有效搜索空间**，每次通过中点对比缩小一半范围：
- **边界定义**：
  - IndexLow：搜索空间的最小索引（初始为0）；
  - IndexHigh：搜索空间的最大索引（初始为length(A)-1）。
- **中点计算**：\(IndexMid = Floor((IndexLow + IndexHigh) / 2)\)（Floor为向下取整函数）。
- **边界调整规则**：
  1. 若 \(A[IndexMid] == target\)：找到目标，返回IndexMid；
  2. 若 \(A[IndexMid] < target\)：目标在右半部分，更新 IndexLow = IndexMid + 1；
  3. 若 \(A[IndexMid] > target\)：目标在左半部分，更新 IndexHigh = IndexMid - 1。

### 3. 示例演示（搜索目标15）
- 初始状态：IndexLow=0，IndexHigh=11（覆盖整个数组）；
- 第1步：中点IndexMid=5（值=11<15），调整IndexLow=6（丢弃左半部分）；
- 第2步：新中点IndexMid=8（值=30>15），调整IndexHigh=7（丢弃右半部分）；
- 第3步：新中点IndexMid=6（值=15=目标），返回索引6。
- 核心优势：每次对比仅需1次，即可丢弃一半搜索空间。


## 五、目标值不存在的处理
### 1. 终止条件
当 \(IndexHigh < IndexLow\) 时，说明搜索空间耗尽，目标值不存在，返回-1。

### 2. 示例（搜索目标10，数组中无该值）
- 逐步调整边界后，最终IndexHigh < IndexLow，算法确认目标不存在。
- 备注：可优化逻辑提前终止（如IndexHigh对应值<目标），但为保持代码简洁，默认保留基础实现。


## 六、二分查找实现（伪代码）
```
BinarySearch(Array: A, Integer: target):
    Integer: IndexHigh = length(A) - 1  # 初始化上界
    Integer: IndexLow = 0  # 初始化下界
    WHILE IndexLow <= IndexHigh:  # 搜索空间未耗尽
        Integer: IndexMid = Floor((IndexHigh + IndexLow) / 2)  # 计算中点
        IF A[IndexMid] == target:
            return IndexMid  # 找到目标，返回索引
        ELSE IF A[IndexMid] < target:
            IndexLow = IndexMid + 1  # 目标在右半部分，调整下界
        ELSE:
            IndexHigh = IndexMid - 1  # 目标在左半部分，调整上界
    return -1  # 目标不存在
```

### 关键说明
- 循环条件：`IndexLow <= IndexHigh` 确保不遗漏最后一个可能的元素；
- 失败处理：返回-1是常用方式，也可抛异常等，需在代码/文档中明确说明，避免调用错误；
- 中点计算：向下取整避免索引越界（适用于奇数/偶数长度的搜索空间）。


## 七、适应性应用：从离散到连续数据
二分查找不仅适用于**离散的列表/数组**（固定索引的离散项），还可适配**连续数据**（无预设索引，基于值的范围）。

### 示例：调优咖啡粉量
- 问题：确定最优咖啡粉量（强咖啡派推荐5汤匙，淡咖啡派推荐0.5汤匙）；
- 边界定义：LowerBound=0汤匙（温水），UpperBound=5汤匙（过浓）；
- 核心逻辑：每次取中点作为测试量（如2.5汤匙），根据口感调整边界：
  - 过浓：UpperBound=2.5（目标在左半范围）；
  - 过淡：LowerBound=1.25（目标在右半范围）；
- 终止条件：\(UpperBound - LowerBound < 阈值\)（连续数据无精确解，追求“足够接近”）。

### 延伸：二分法（Bisection Search）
用于寻找函数零点（即 \(f(x)=0\) 的x值）：通过跟踪函数值正负的边界，反复二分区间，逐步逼近零点。


## 八、时间复杂度对比
| 算法         | 最坏情况时间复杂度 | 核心原因                     |
|--------------|--------------------|------------------------------|
| 线性查找     | 线性时间（O(N)）   | 必须遍历所有元素             |
| 二分查找     | 对数时间（\(log_2N\)） | 每次丢弃一半搜索空间，仅需对数次对比 |

### 关键补充
- 二分查找每步需额外计算中点、调整边界，但大数据集下，“对数次对比”的优势远超过单次步骤的额外开销；
- 特殊场景：目标在列表开头时，线性查找更快；极小列表（如2个元素）无需二分，直接对比更高效。


## 九、核心意义总结
二分查找成为CS入门核心主题的原因：
1. **逻辑简洁**：易理解、易实现、易分析正确性；
2. **思维示范**：展示计算思维的核心——利用**问题/数据的结构**（此处是“有序”）设计高效方案；
3. **效率飞跃**：将最坏情况从线性时间优化为对数时间，随数据量增长，优势愈发显著；
4. **普适性**：连接离散与连续数据，为后续树结构、二分法等复杂算法奠定基础。
