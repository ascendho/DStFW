# 前缀树

## 一、前缀树的核心定位：解决BST存储字符串的痛点
### 1. 引入背景：BST存储字符串的局限性
二叉搜索树（BST）可存储字符串（按字典序排序），但存在致命缺陷，催生了前缀树（Trie，发音“try”）：
- **字符串比较成本高**：BST中每次节点比较需逐字符对比字符串，直到找到首个不同字符（如“Jeremy’s Gourmet High Caffeine Experience: Medium Roast”与“City Roast”需对比大量前缀字符），且比较次数随树深增加，总成本=树深×字符串长度。
- **未利用字符串特性**：字符串具有“顺序性”（逐字符构成）和“字符有限性”（如英文仅26个字母），BST的二叉分支未充分利用这些结构，导致效率浪费。

### 2. 前缀树的核心价值
- 本质：**基于字符串前缀的多叉树数据结构**，将“字符串比较”转化为“字符级分支查找”，每一层仅需1次字符匹配，无需完整字符串对比。
- 核心优势：操作成本（搜索/增删）与存储的字符串数量无关，仅与目标字符串长度成正比（O(L)，L为字符串长度），适合大量相似前缀字符串的动态场景。


## 二、前缀树的结构组成
### 1. 节点结构（TrieNode）
- 核心组件：
  1. `is_entry`：布尔值，标记当前节点是否代表“有效条目”（即完整字符串，而非仅前缀）。
     - 例：存储“COFFEE”时，“COFFE”节点的`is_entry=False`（仅前缀），“COFFEE”节点的`is_entry=True`（有效字符串）。
  2. `children`：字符映射的子节点数组（或哈希表），数组长度=字符集大小（如英文26个字母对应26位数组），每个索引对应一个字符，值为子节点指针（空指针表示无该字符分支）。
  3. 可选辅助数据：如字符串出现次数、定义、关联信息（如产品序列号对应的购买记录）。
- 伪代码定义：
  ```
  TrieNode {
      Boolean: is_entry  // 标记是否为有效条目
      Array of TrieNodes: children  // 字符→子节点映射
      [AuxData: ...]  // 可选辅助数据（如计数、定义）
  }
  ```

### 2. 树的整体结构（Trie）
- 根节点（Root）：固定存在（即使树为空），代表“空前缀”，`is_entry=False`（空字符串除外）。
- 节点分类：
  - 内部节点：至少有一个子节点的节点（可能是前缀，也可能是有效条目，如存储“CAT”和“CATALOG”时，“CAT”节点是内部节点且`is_entry=True`）。
  - 叶子节点：无子女的节点，必然是有效条目（`is_entry=True`）。
- 存储特性：仅为“非空分支”创建节点，避免浪费空间（如英文单词的前缀节点仅创建实际存在的字符分支，无需为26个字母都分配节点）。

### 3. 结构类比
- 类似“多层文件柜”：根节点=大楼，第一层=首字母楼层，第二层=次字母房间，第三层=字母文件柜…… 每个层级按字符分支，最终到达“有效条目”对应的文件。


## 三、前缀树的核心操作（均为O(L)复杂度，L为字符串长度）
### 1. 搜索操作：查找目标字符串是否存在
#### （1）核心逻辑
从根节点出发，按目标字符串的字符顺序，逐层查找对应子节点：
- 若某字符对应的子节点为空→目标字符串不存在；
- 遍历完所有字符后，检查当前节点的`is_entry`是否为`True`（区分“前缀存在”和“完整字符串存在”）。

#### （2）实现步骤（递归+包装函数）
1. 包装函数（隐藏根节点和初始索引）：
   ```
   TrieSearch(Trie: trie, String: target):
       return TrieNodeSearch(trie.root, target, 0)  // 索引0表示从首字符开始
   ```
2. 递归搜索函数：
   ```
   TrieNodeSearch(TrieNode: current, String: target, Integer: index):
   1. 若 index == 字符串长度：  // 遍历完所有字符
       return current.is_entry ? current : null  // 检查是否为有效条目
   2. 取目标字符串的第index个字符（next_letter）；
   3. 通过LetterToIndex函数将字符映射为children数组索引（next_index）；
   4. 若 current.children[next_index] 为空→返回null（无该分支）；
   5. 否则递归调用 TrieNodeSearch(当前子节点, target, index+1)。
   ```

#### （3）示例
- 搜索“ZONK”（图6-7）：根节点→Z子节点→O子节点→N子节点→K子节点，遍历4个节点（字符串长度4），检查K节点`is_entry=True`→找到目标。
- 搜索“ZIPPY”：根节点→Z子节点，无I子节点→返回null（不存在）。


### 2. 插入操作：添加新字符串
#### （1）核心逻辑
与搜索流程一致，按字符逐层遍历，遇到空分支时创建新节点，遍历结束后标记当前节点为有效条目（`is_entry=True`）。
- 特点：插入一个字符串可能创建多个节点（对应字符串的每个字符），共享已有前缀节点（如插入“ZOUNDS”和“ZONK”时，共享“Z”“O”节点）。

#### （2）实现步骤
1. 包装函数：
   ```
   TrieInsert(Trie: trie, String: new_value):
       TrieNodeInsert(trie.root, new_value, 0)  // 根节点固定存在，无需特殊处理
   ```
2. 递归插入函数：
   ```
   TrieNodeInsert(TrieNode: current, String: new_value, Integer: index):
   1. 若 index == 字符串长度：  // 遍历完所有字符
       current.is_entry = True  // 标记为有效条目
       [更新辅助数据（如计数+1）]
       return
   2. 取第index个字符（next_letter），映射为数组索引（next_index）；
   3. 若 current.children[next_index] 为空：
       创建新TrieNode，赋值给 current.children[next_index]
   4. 递归调用 TrieNodeInsert(当前子节点, new_value, index+1)。
   ```

#### （3）示例
- 插入“EEK”（图6-8）：根节点→E子节点（已存在）→无E子节点→创建E子节点（前缀“EE”）→无K子节点→创建K子节点，标记K节点`is_entry=True`。


### 3. 删除操作：移除目标字符串（最复杂）
#### （1）核心逻辑
1. 向下遍历找到目标字符串的末尾节点，将其`is_entry`设为`False`（取消有效条目标记）；
2. 向上回溯，删除“无用节点”：若当前节点不是有效条目，且所有子节点均为空（无其他字符串依赖该前缀），则删除该节点，直到遇到“有效条目节点”或“有非空子节点的节点”。

#### （2）实现步骤
1. 包装函数：
   ```
   TrieDelete(Trie: trie, String: target):
       TrieNodeDelete(trie.root, target, 0)
   ```
2. 递归删除函数（返回布尔值：是否可安全删除当前节点）：
   ```
   TrieNodeDelete(TrieNode: current, String: target, Integer: index):
   1. 若 index == 字符串长度：  // 到达目标字符串末尾
       if current.is_entry:
           current.is_entry = False  // 取消有效条目标记
       return True  // 标记可尝试删除当前节点
   2. 取第index个字符，映射为索引（next_index）；
   3. 若 current.children[next_index] 为空→返回False（目标字符串不存在，无需删除）；
   4. 递归调用 TrieNodeDelete(子节点, target, index+1)，获取是否可删除子节点；
   5. 若子节点可删除→将 current.children[next_index] 设为null；
   6. 检查当前节点是否“可安全删除”：
       return (current.is_entry == False) AND (所有子节点均为空)
   ```

#### （3）示例
- 删除“YIPPEE”（图6-9）：
  1. 向下遍历至“YIPPEE”节点，设`is_entry=False`；
  2. 回溯：“YIPPEE”节点无子女→删除；“YIPPE”节点无子女且`is_entry=False`→删除；“YIPP”节点无子女且`is_entry=False`→删除；
  3. 到达“YIP”节点（`is_entry=True`，有效条目）→停止删除。


## 四、前缀树与字符串BST的核心对比
| 对比维度                | 字符串BST                          | 前缀树（Trie）                      |
|-------------------------|-----------------------------------|-------------------------------------|
| 搜索成本                | O(logN × L)（N=条目数，L=字符串长度） | O(L)（仅与字符串长度相关，与N无关）  |
| 比较方式                | 节点处完整字符串逐字符对比        | 每层1次字符映射查找，无字符串对比    |
| 内存开销                | 每个条目1个节点，2个指针          | 每个字符1个节点，字符集大小个指针（如26），但共享前缀节点 |
| 适用场景                | 少量字符串、前缀差异大            | 大量字符串、相似前缀多（如字典、序列号） |
| 动态增删效率            | O(logN)（依赖树平衡）              | O(L)（稳定高效，与N无关）            |
| 前缀匹配支持            | 不支持（需遍历所有节点）           | 天然支持（如查找所有“ZO”开头的字符串）|


## 五、前缀树的优缺点
### 1. 优点
- 高效操作：搜索、增删均为O(L)，适合动态场景（如实时字典校验、订单号跟踪）。
- 前缀匹配：天然支持“前缀查询”（如查找所有以“APP”开头的单词），无需额外遍历。
- 共享前缀：相似前缀的字符串共享节点，减少重复存储（如“ZOUNDS”和“ZONK”共享“Z”“O”节点）。

### 2. 缺点
- 内存开销大：每个字符需一个节点，且每个节点需存储字符集大小的指针（如英文26个），空分支指针浪费空间（可优化为哈希表存储子节点，减少空指针）。
- 字符集依赖：若字符集过大（如Unicode），数组实现不可行，需用哈希表等动态映射结构，增加少量查询开销。


## 六、典型应用场景
1. **字典与拼写检查**：文字处理器中实时校验单词是否存在（如拼写错误高亮），辅助数据存储单词定义。
2. **结构化标签跟踪**：存储序列号、SKU码、型号等短字符序列，按前缀快速查找（如按型号前缀查询产品注册信息）。
3. **前缀匹配功能**：自动补全（如搜索框输入“mic”提示“microphone”“microwave”）、通讯录按姓名前缀查找。
4. **字符串去重与计数**：统计字符串出现次数（如日志中关键词频次），通过`is_entry`和辅助计数实现。


## 七、核心意义与延伸
### 1. 核心思想
前缀树是“数据结构适配数据特性”的典型案例：利用字符串的“顺序性”和“字符有限性”，将BST的二叉分支升级为多叉字符分支，把高成本的字符串对比转化为低成本的字符映射，体现了“利用数据内在结构优化算法效率”的核心主题。

### 2. 优化方向
- 内存优化：用哈希表（而非数组）存储子节点，仅为存在的字符分配空间，适用于大字符集（如Unicode）。
- 性能优化：结合压缩前缀树（Compact Trie），合并无分支的连续节点（如“EEK”的“E→E→K”可合并为“EEK”节点），减少节点数量。
