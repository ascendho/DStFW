# 图

## 一、核心定义与本质
### 1. 基础构成
- 核心元素：由**节点（Nodes）** 和**边（Edges）** 组成，边连接成对节点，是对现实世界中“关联关系”的抽象建模。
- 核心价值：与前序数据结构不同，图的结构由数据本身的关联关系自然形成，而非为优化算法刻意设计；算法需适配数据的固有结构，体现“数据结构驱动算法设计”的核心思想。

### 2. 图的核心分类（按边的属性）
| 分类维度       | 类型                | 定义与示例                                                                 |
|----------------|---------------------|----------------------------------------------------------------------------|
| 边的方向性     | 无向图（Undirected）| 边是双向关系，如道路、双向好友；可用一对反向有向边等效表示。                 |
|                | 有向图（Directed）  | 边是单向关系，如单向街道、任务依赖（A→B表示A需先于B执行）、单相思。         |
| 边的权重       | 无权图（Unweighted）| 边仅表示“是否关联”，无额外信息。                                             |
|                | 加权图（Weighted）  | 边附带数值（权重），表示关联的成本/距离/强度，如道路长度、通信延迟。         |
| 特殊结构       | 有向无环图（DAG）  | 有向边且无循环路径（不会从某节点出发后返回该节点），适用于任务排序等场景。   |

### 3. 典型应用场景
- 社交网络：节点=人，边=好友关系（无向）或关注关系（有向）；
- 交通网络：节点=城市/路口，边=道路，权重=距离/时间；
- 任务调度：节点=任务，边=依赖关系（有向），如冲咖啡的步骤（磨豆→放滤网）；
- 计算机网络：节点=设备，边=网络连接；
- 网页链接：节点=网页，边=超链接（有向）。


## 二、图的存储表示（两种核心方式）
图的存储核心是“记录节点与边的关联关系”，两种方式各有优劣，适配不同场景：

### 1. 邻接表（Adjacency List）
#### （1）结构设计
- 核心逻辑：每个节点维护一个“相邻节点/边的列表”，图整体存储为节点数组。
- 数据结构定义（伪代码）：
```
// 边结构（存储方向、权重等辅助信息）
Edge {
  Integer: from_node  // 起点节点ID
  Integer: to_node    // 终点节点ID
  Float: weight       // 边的权重（无权图可省略）
}

// 节点结构
Node {
  String: name        // 节点名称
  Integer: id         // 节点唯一ID（对应图中数组索引）
  Array of Edges: edges  // 该节点的所有出边
}

// 图结构
Graph {
  Integer: num_nodes  // 节点总数
  Array of Nodes: nodes  // 节点数组
}
```
- 示意图：节点A的列表存储其邻居B、C、D，节点B的列表存储其邻居A、F等，仅记录直接关联关系。

#### （2）特点
- 优点：内存高效（仅存储实际存在的边，无冗余）；适配稀疏图（边数远小于节点数的平方）；便于遍历节点的所有邻居。
- 缺点：查询“两节点是否直接相连”需遍历对应节点的列表，效率低于邻接矩阵。

### 2. 邻接矩阵（Adjacency Matrix）
#### （1）结构设计
- 核心逻辑：用`n×n`矩阵（n为节点数）表示图，矩阵元素`matrix[i][j]`表示“节点i到节点j的边的权重”；若为0则表示无直接边。
- 示意图：行=起点，列=终点，如`matrix[A][B]=1.5`表示A到B的边权重为1.5，`matrix[B][A]=0`表示B到A无直接边。

#### （2）特点
- 优点：查询“两节点是否直接相连”为O(1)（直接访问矩阵元素）；适合稠密图（边数接近节点数的平方）；全局视图清晰。
- 缺点：内存开销大（固定为`n²`，与边数无关）；遍历节点的所有邻居需扫描整行，效率低。

### 3. 两种表示方式对比
| 特性                | 邻接表                | 邻接矩阵              |
|---------------------|-----------------------|-----------------------|
| 内存开销            | O(n+e)（n=节点数，e=边数）| O(n²)                 |
| 查询两节点直接连接  | O(degree(v))（v的度） | O(1)                  |
| 遍历节点所有邻居    | O(degree(v))          | O(n)                  |
| 适用场景            | 稀疏图、频繁遍历邻居  | 稠密图、频繁查询边存在性 |


## 三、图的搜索方式
图的搜索核心是“按特定顺序遍历节点”，顺序由数据结构（栈/队列）决定，适配不同需求：
| 搜索方式       | 核心数据结构 | 遍历逻辑                                                                 | 适用场景                     |
|----------------|--------------|--------------------------------------------------------------------------|------------------------------|
| 深度优先搜索（DFS） | 栈（Stack）  | 优先沿当前路径“深挖”，直到死胡同后回溯，再探索其他分支（如迷宫探险）。     | 路径查找、连通性检测、拓扑排序辅助 |
| 广度优先搜索（BFS） | 队列（Queue）| 按“层级”遍历，先访问起点的所有直接邻居，再访问邻居的邻居（如涟漪扩散）。   | 最短路径（无权图）、层级关系查询 |
| 最佳优先搜索（Best-First） | 优先级队列 | 按自定义评分函数排序，优先访问高分节点（如按距离排序的路径搜索）。         | 启发式搜索（如找最近的咖啡店） |


## 四、三大核心图算法（原理+伪代码+关键细节）
### 1. 迪杰斯特拉算法（Dijkstra’s Algorithm）—— 最短路径问题
#### （1）核心用途
- 问题定义：在**非负权重图**（边权≥0）中，找到从“起点节点”到所有其他节点的**最短路径**（总权重最小）。
- 示例场景：从酒店出发，找前往多个咖啡店的最短路线（节点=路口/咖啡店，边权=道路距离）。

#### （2）核心思想
- 贪心策略：每次选择“当前未访问节点中距离起点最近的节点”，以该节点为跳板，更新其邻居的最短距离（若经当前节点的路径更短）。
- 关键约束：边权必须非负，否则可能出现“更新后距离更短”的无限循环。

#### （3）伪代码关键步骤
```
输入：图G、起点节点索引from_node_index
输出：各节点到起点的最短距离（distance数组）、路径前驱（last数组，用于回溯路径）
1. 初始化辅助结构：
   - distance数组：初始值为无穷大（inf），distance[from_node_index] = 0（起点距离为0）；
   - last数组：初始值为-1，记录每个节点的最短路径前驱节点；
   - unvisited集合：包含所有节点的索引（未访问节点集合）。
2. 循环处理未访问节点（直到unvisited为空）：
   a. 从unvisited中选择distance最小的节点next_index，标记为当前节点current；
   b. 将next_index从unvisited中移除；
   c. 遍历current的所有边：
      i. 计算新路径距离：new_dist = distance[current.id] + 边的权重；
      ii. 若new_dist < distance[边的终点to_node]，则更新：
          distance[to_node] = new_dist；
          last[to_node] = current.id。
3. 返回distance数组和last数组（可通过last回溯具体路径）。
```

#### （4）优化技巧
- 用**最小堆（优先队列）** 替代“遍历unvisited找最小distance”，将每次选节点的时间复杂度从O(n)降至O(log n)，整体效率更高。

### 2. 普里姆算法（Prim’s Algorithm）—— 最小生成树问题
#### （1）核心用途
- 问题定义：在**无向加权图**中，找到“最小生成树（MST）”—— 包含所有节点且总边权最小的无环子图（即“用最少成本连接所有节点”）。
- 示例场景：城市修路规划，用最少的总造价铺设道路，确保所有城市连通（节点=城市，边权=修路成本）。

#### （2）核心思想
- 贪心策略：从任意起点开始，逐步扩展“已连通节点集合”；每次选择“连接已连通集合与未连通集合的最小权边”，将对应未连通节点加入集合，直到所有节点连通。
- 关键特性：最小生成树可能不唯一，但总边权一定最小。

#### （3）伪代码关键步骤
```
输入：图G
输出：最小生成树的边集合mst_edges
1. 初始化辅助结构：
   - distance数组：初始值为无穷大（inf），记录每个未连通节点到已连通集合的最小边权；
   - last数组：初始值为-1，记录每个节点连接到已连通集合的前驱节点；
   - unvisited集合：包含所有节点的索引；
   - mst_edges集合：存储最小生成树的边（初始为空）。
2. 循环处理未访问节点（直到unvisited为空）：
   a. 从unvisited中选择distance最小的节点next_id，标记为当前节点current；
   b. 将next_id从unvisited中移除；
   c. 若last[next_id] != -1（非起点），将“last[next_id]→next_id”的边加入mst_edges；
   d. 遍历current的所有边：
      i. 若边的终点to_node在unvisited中，且边权 < distance[to_node]，则更新：
          distance[to_node] = 边权；
          last[to_node] = current.id。
3. 返回mst_edges集合。
```

#### （4）与迪杰斯特拉算法的区别
| 算法         | 核心目标               | 距离数组含义                     | 适用图类型       |
|--------------|------------------------|----------------------------------|------------------|
| 迪杰斯特拉   | 起点到所有节点的最短路径 | 节点到起点的总路径长度           | 有向/无向、非负权 |
| 普里姆       | 最小生成树（连接所有节点）| 节点到“已连通集合”的最小边权     | 无向、加权       |

### 3. 卡恩算法（Kahn’s Algorithm）—— 拓扑排序问题
#### （1）核心用途
- 问题定义：对**有向无环图（DAG）** 进行“拓扑排序”—— 节点排序满足：若存在边A→B，则A在排序中一定位于B之前。
- 示例场景：任务调度（如冲咖啡的步骤排序）、程序编译依赖（先编译被依赖的模块）。

#### （2）核心思想
- 基于“入度”的贪心策略：入度=节点的 incoming 边数（即依赖的前置节点数）；每次选择“入度为0”的节点（无未完成依赖），移除该节点及其出边（减少后续节点的入度），重复直到所有节点排序完成。
- 关键约束：图必须无环，否则存在“循环依赖”，无法拓扑排序（排序结果会不完整）。

#### （3）伪代码关键步骤
```
输入：有向无环图G
输出：拓扑排序后的节点数组sorted
1. 初始化辅助结构：
   - sorted数组：存储排序结果（初始为空）；
   - count数组：记录每个节点的入度（初始为0）；
   - next栈：存储“入度为0”的节点（初始为空）。
2. 统计所有节点的入度：
   遍历G中所有节点的边，对每条边（from→to），执行count[to] += 1。
3. 初始化next栈：
   遍历所有节点，若count[node.id] == 0，将节点压入next栈。
4. 循环处理next栈（直到栈为空）：
   a. 弹出栈顶节点current，将其加入sorted数组末尾；
   b. 遍历current的所有出边：
      i. 对边的终点to_node，执行count[to_node] -= 1（移除current的依赖）；
      ii. 若count[to_node] == 0，将to_node压入next栈。
5. 返回sorted数组（若数组长度≠节点总数，说明图有环，无法拓扑排序）。
```

#### （4）示例流程
- 初始状态：找到入度为0的节点A，加入排序；
- 移除A的出边：减少其邻居C的入度至0，将C加入排序；
- 移除C的出边：减少其邻居E的入度至0，将E加入排序；
- 依次处理E、D、F、B，最终得到拓扑排序结果（如A→C→E→D→F→B）。


## 五、核心价值与关键要点
### 1. 核心价值
- 建模能力强：可抽象任意“关联关系”场景，是计算机科学中最通用的数据结构之一；
- 算法与数据结构深度耦合：图的固有结构（边的方向、权重、环）决定了算法设计，而算法通过遍历边、处理节点关联来解决问题；
- 工程实用性广：覆盖路径规划、任务调度、网络设计、依赖分析等多个核心场景。

### 2. 关键要点
- 图的类型决定算法选择：如无环→拓扑排序（卡恩）、非负权→最短路径（迪杰斯特拉）、无向加权→最小生成树（普里姆）；
- 存储表示影响效率：稀疏图优先用邻接表（省内存），稠密图优先用邻接矩阵（查边快）；
- 贪心策略是核心：三大算法均基于贪心思想（选当前最优），但需满足特定约束（如迪杰斯特拉的非负权、卡恩的无环）。

### 3. 延伸思考
- 图算法的扩展：如处理负权边的贝尔曼-福特算法、处理最大流的福特-富尔克森算法、无向图连通性检测的并查集优化等；
- 实际工程优化：如用堆优化迪杰斯特拉和普里姆的时间复杂度，用邻接表+入度数组优化卡恩算法的效率。
