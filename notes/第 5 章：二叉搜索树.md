# 二叉搜索树


## 一、二叉搜索树的核心概念
### 1. 定义与定位
- **本质**：基于二分查找算法思想构建的**动态数据结构**，融合了二分查找的高效性（O(logN)级搜索）与动态数据结构的适应性（支持高效增删），区别于静态的有序数组（仅支持高效搜索，增删成本高）。
- **核心价值**：将二分查找的“比较-剪枝”逻辑编码到数据结构本身，通过节点间的有序关系实现高效操作。


### 2. 结构组成
#### （1）节点结构
- **最小构成**：值（或键）、左孩子指针、右孩子指针（可空）、**可选父节点指针**（简化删除操作，支持从下往上遍历）。
- **扩展信息**：可存储辅助数据（如咖啡的详细记录、时间戳对应的事件），或指向复合数据结构的指针，扩展BST的实用场景（如索引功能）。
- **伪代码定义**：
  ```
  TreeNode {
      Type: value  // 核心键值
      TreeNode: left  // 左孩子（值更小）
      TreeNode: right  // 右孩子（值更大）
      TreeNode: parent  // 父节点（可选，优化删除）
      [AuxData: ...]  // 辅助数据（可选）
  }
  ```

#### （2）树的层级结构
- **根节点（Root）**：树的起点，所有操作（搜索、增删）均从根开始；空树时根为null。
- **节点分类**：
  - 叶子节点（Leaf）：无左/右孩子的节点（末端节点）。
  - 内部节点（Internal Node）：至少有一个孩子的节点（中间节点，如父节点、子树的根）。
- **树的存储特性**：节点在内存中分散存储，仅通过指针关联（类似链表），而非连续空间（区别于数组）。


### 3. 关键性质（BST Property）
- **核心规则**：对任意节点N：
  1. N的左子树中所有节点的值 **< N的值**；
  2. N的右子树中所有节点的值 **> N的值**；
  3. 默认不允许重复值（若需支持，需修改性质，如将重复值放入左/右子树；文档中聚焦无重复场景，与跳表、哈希表保持一致）。
- **性质作用**：保证“每次比较可剪枝一半搜索空间”，是高效操作的基础。


## 二、二叉搜索树的核心操作
所有操作的时间复杂度均与**树的深度**相关：平衡树中为O(logN)，不平衡树中最坏为O(N)（链表化）。


### 1. 搜索操作（查找目标值）
#### （1）核心逻辑
- 从根节点出发，通过“目标值与当前节点值的比较”决定遍历方向：
  - 目标值 < 当前值 → 遍历左子树（右子树所有值均更大，可剪枝）；
  - 目标值 > 当前值 → 遍历右子树（左子树所有值均更小，可剪枝）；
  - 相等 → 找到目标节点；
  - 遍历至null（无对应子树）→ 目标值不存在。

#### （2）两种实现方式
| 实现方式 | 步骤                                                                 | 伪代码核心逻辑                                                                 |
|----------|----------------------------------------------------------------------|------------------------------------------------------------------------------|
| 递归实现 | 1. 基线条件：当前节点为null → 返回null；<br>2. 若当前值=目标值 → 返回节点；<br>3. 递归遍历左/右子树。 | `FindValue(current, target)`：先判空/判相等，再递归左（小）/右（大）子树。       |
| 迭代实现 | 1. 初始化当前节点为根；<br>2. 循环：当前节点非null且值≠目标值 → 调整当前节点为左/右孩子；<br>3. 循环结束 → 返回当前节点（找到或null）。 | `FindValueItr(root, target)`：用while循环替代递归，避免栈溢出风险。              |

#### （3）示例
- 搜索值63：从根50→右子树67→左子树（63<67）→ 遍历4个节点后找到，剪枝大量无效节点（如左子树11个节点无需检查）。


### 2. 插入操作
#### （1）核心逻辑
- 与搜索流程高度一致：先按BST性质遍历至“死胡同”（叶子节点或单孩子节点的空孩子位置），再创建新节点插入，同时维护父节点指针。
- **重复值处理**：文档中默认不允许重复，若遇重复值可“更新节点辅助数据”（如计数器累加）；若需支持重复，可修改性质（如重复值放入右子树）。

#### （2）实现步骤
1. **包装函数（处理空树）**：若树为空，新节点直接作为根；否则调用递归插入函数。
   ```
   InsertTreeNode(tree, new_value):
       if tree.root == null: tree.root = TreeNode(new_value)
       else: InsertNode(tree.root, new_value)
   ```
2. **递归插入（找位置插入）**：
   - 若新值=当前值 → 更新辅助数据，返回；
   - 若新值<当前值：左孩子非null则递归左子树，否则创建左孩子并设父节点；
   - 若新值>当前值：右孩子非null则递归右子树，否则创建右孩子并设父节点。

#### （3）复杂度
- 与搜索一致：O(树深)，平衡树中O(logN)，不平衡树中O(N)。


### 3. 删除操作（最复杂，分3种情况）
#### 核心原则
- 删除后需**保持BST性质**，且维护父/子节点指针关联；父节点指针在此步骤中至关重要（避免遍历查找父节点）。

#### （1）情况1：删除叶子节点（无孩子）
- 步骤：直接删除节点，将其父节点的对应孩子指针（左/右）设为null。
- 示例：删除节点58 → 其父节点的左指针设为null，父节点可能变为新叶子。


#### （2）情况2：删除单孩子节点（仅左或右孩子）
- 步骤：“提升”孩子节点，替代被删节点的位置（即让孩子的父节点改为被删节点的父节点，父节点的对应孩子指针改为孩子节点）。
- 示例：删除节点17（仅右孩子21）→ 节点17的父节点（14）直接指向21，21的父节点改为14。


#### （3）情况3：删除双孩子节点（最复杂）
- 核心问题：无法直接提升任一孩子（会破坏BST性质），需找“替代节点”——**后继节点**（保持BST有序性的最小干扰节点）。
- 后继节点定义：被删节点右子树中的**最小节点**（即右子树最左节点），其特点是“最多只有右孩子”（避免递归触发情况3）。
- 步骤：
  1. 找被删节点的后继节点（右子树遍历至最左节点）；
  2. 删除后继节点（后继节点最多单孩子，用情况1/2处理）；
  3. 用后继节点替代被删节点：
     - 后继节点的父节点设为被删节点的父节点，父节点的对应孩子指针设为后继；
     - 后继节点的左/右孩子分别设为被删节点的左/右孩子，并更新左/右孩子的父节点为后继。
- 示例：删除节点81（双孩子）→ 找后继91（右子树最小）→ 删除91（情况1）→ 91替代81的位置，关联父/子节点。


#### （4）删除函数伪代码核心框架
```
RemoveTreeNode(tree, node):
    1. 判空（树空或节点null）→ 返回；
    2. 情况1（叶子）→ 父节点对应指针设为null；
    3. 情况2（单孩子）→ 提升孩子节点；
    4. 情况3（双孩子）→ 找后继→删后继→替代被删节点；
    5. （可选）清理被删节点指针（parent/left/right设为null）。
```


## 三、BST与有序数组的对比：动态场景的优势
| 维度                | 有序数组（静态）                          | 二叉搜索树（动态）                        |
|---------------------|-------------------------------------------|-------------------------------------------|
| 搜索效率            | O(logN)（二分查找）                       | O(logN)（平衡时）/ O(N)（不平衡时）        |
| 插入/删除效率       | O(N)（需移动元素，如插入到中间）          | O(logN)（平衡时）/ O(N)（不平衡时）        |
| 适用场景            | 数据静态（无增删或极少），仅需搜索        | 数据动态（频繁增删+搜索），如订单列表、日志 |
| 内存开销            | 无指针开销（连续存储）                    | 指针开销（父/左/右指针）                  |

- 关键结论：**动态数据场景下，BST的增删效率远优于有序数组**，是其核心价值所在。


## 四、BST的致命问题：不平衡树
### 1. 不平衡的原因
- 当插入数据呈“有序趋势”时（如按递增时间戳、递增ID插入），BST会退化为**单向链表**（所有节点仅右孩子或仅左孩子）。
- 示例：咖啡日志按时间戳（1,2,3,...）插入 → 所有节点仅右孩子，树深=节点数N。


### 2. 不平衡的影响
- 操作复杂度从O(logN)骤降为O(N)（与链表一致），失去BST的高效性。


### 3. 解决办法
#### （1）平衡BST变种（自动维护平衡）
- 常见类型：红黑树、2-3树、B树（文档后续章节聚焦B树），通过“旋转”“颜色调整”等机制，插入/删除时自动平衡树，保证树深为O(logN)。
- trade-off：操作逻辑更复杂（如红黑树的颜色翻转与旋转）。

#### （2）批量构建平衡BST（初始数据已知时）
- 适用场景：初始有大量有序数据，需构建平衡树（避免逐次插入导致不平衡）。
- 核心思想：利用有序数组的“中间元素”作为根，递归构建左右子树（保证左右子树节点数接近）。
- 步骤：
  1. 输入有序数组，取中间元素作为当前节点；
  2. 左子树：递归处理数组左半部分（小于中间元素）；
  3. 右子树：递归处理数组右半部分（大于中间元素）；
  4. 无需复制数组，仅用“高低索引”跟踪当前处理范围（优化空间）。
- 优势：构建的树天然平衡，树深为O(logN)。


## 五、BST的意义与后续延伸
### 1. 核心价值
- 是“数据结构适配问题”的典型案例：通过节点分支结构，将“二分查找逻辑”固化到数据存储中，实现动态数据的高效操作。
- 奠定分支数据结构的基础：后续复杂数据结构（如trie树、B树、红黑树）均基于“分支+有序性”思想扩展。

### 2. 后续延伸
- 文档下一章引入**trie树**（前缀树）：将BST的“二叉分支”扩展为“多叉分支”，优化字符串等“前缀匹配”场景的搜索效率（如字典、自动补全）。


## 六、关键公式与复杂度总结
| 操作       | 平衡BST复杂度 | 不平衡BST复杂度 | 核心影响因素       |
|------------|---------------|-----------------|--------------------|
| 搜索（递归/迭代） | O(logN)       | O(N)            | 树深（logN vs N）  |
| 插入       | O(logN)       | O(N)            | 树深               |
| 删除       | O(logN)       | O(N)            | 树深（含找后继）   |
| 批量构建（有序数组） | O(N)        | -               | 数组遍历+递归（无额外开销） |

- 平衡BST的树深公式：N个节点的完美平衡树，树深≈log₂N（每层节点数翻倍）。
