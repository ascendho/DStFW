# 栈与队列

## 一、核心概念：两种基于“插入顺序”的线性数据结构
栈和队列是**仅依赖数据插入顺序**检索元素的线性数据结构，核心区别在于“元素取出顺序”，二者均支持高效的插入/删除操作，是深度优先搜索（DFS）、广度优先搜索（BFS）等算法的基础。

| 对比维度         | 栈（Stack）                | 队列（Queue）              |
|------------------|-----------------------------|-----------------------------|
| 核心特性         | 后进先出（LIFO, Last-In-First-Out） | 先进先出（FIFO, First-In-First-Out） |
| 类比场景         | 沙拉吧的生菜桶（新菜叠在顶部，取菜从顶部拿） | 咖啡店排队（新顾客排尾，服务从队首开始） |
| 核心操作         | Push（入栈）、Pop（出栈）   | Enqueue（入队）、Dequeue（出队） |
| 辅助操作         | 查看栈顶元素（Top）、判断空  | 查看队首元素（Front）、判断空  |


## 二、栈（Stacks）
### 1. 定义与核心规则
- 元素仅从“栈顶”插入和删除，最新插入的元素最先被取出（LIFO）。
- 例：插入顺序 `1,2,3,4,5` → 出栈顺序 `5,4,3,2,1`。

### 2. 实现方式（数组/链表）
栈可通过**数组**或**链表**实现，两种方式各有优劣，核心操作（Push/Pop）均为 O(1) 时间复杂度（数组扩容除外）。

#### （1）数组实现（Stacks as Arrays）
- 结构设计：
  - 用数组存储元素，额外维护 `top` 指针（初始值 `-1`，标识栈空）。
  - 栈底 → 数组索引 `0`，栈顶 → 数组索引 `top`。
- 核心操作：
  1. Push（入栈）：
     - 步骤：① 检查 `top == 数组容量-1`（栈满），若满则通过“数组加倍”扩容（参考第3章）；② `top += 1`；③ 新元素存入 `array[top]`。
     - 代码逻辑：
       ```
       Push(Stack: s, Type: value):
         IF s.top == s.array_size – 1: 扩容数组
         s.top = s.top + 1
         s.array[s.top] = value
       ```
  2. Pop（出栈）：
     - 步骤：① 检查 `top > -1`（栈非空）；② 取出 `array[top]`；③ `top -= 1`；④ 返回取出的元素（栈空返回 `null`）。
     - 代码逻辑：
       ```
       Pop(Stack: s):
         Type: value = null
         IF s.top > -1:
           value = s.array[s.top]
           s.top = s.top – 1
         return value
       ```
- 优势：操作简单，无指针开销；劣势：需提前预估容量，扩容时有 O(N) 复制成本。

#### （2）链表实现（Stacks as Linked Lists）
- 结构设计：
  - 用单链表存储元素，**头指针（head）直接作为栈顶**（链表左→右为栈顶→栈底，与数组顺序一致）。
  - 无需维护 `top` 指针，头节点即为最新插入的元素。
- 核心操作：
  1. Push（入栈）：新节点插入链表头部（栈顶）。
     - 代码逻辑：
       ```
       Push(Stack: s, Type: value):
         LinkedListNode: node = 新建节点（value）
         node.next = s.head  // 新节点指向原栈顶
         s.head = node       // 头指针更新为新栈顶
       ```
  2. Pop（出栈）：删除链表头部（栈顶）节点。
     - 代码逻辑：
       ```
       Pop(Stack: s):
         Type: value = null
         IF s.head != null:
           value = s.head.value
           s.head = s.head.next  // 头指针指向次栈顶
         return value
       ```
- 优势：动态扩容（无需提前预估容量），无扩容成本；劣势：需额外存储指针，有少量内存开销。


## 三、队列（Queues）
### 1. 定义与核心规则
- 元素从“队尾”插入，从“队首”删除，最早插入的元素最先被取出（FIFO）。
- 例：入队顺序 `1,2,3,4,5` → 出队顺序 `1,2,3,4,5`。

### 2. 实现方式（数组/链表）
队列的关键是高效维护“队首”和“队尾”，链表实现更优（无空间浪费），数组实现需解决“队首空出”的问题。

#### （1）数组实现（Queues as Arrays）
- 结构设计：
  - 用数组存储元素，维护两个指针：`front`（队首索引）、`back`（队尾索引）。
  - 初始状态：`front = back = 0`（或 `front = 0, back = -1`）。
- 核心问题：
  - 出队时 `front` 递增，导致数组前端出现空间隙，若直接扩容会浪费空间。
- 解决方案：**循环数组（Wrap Around）**：
  - 当 `back` 达到数组末尾时，若前端有空隙，`back` 绕回数组起始位置（通过取模运算实现）。
- 核心操作：
  1. Enqueue（入队）：`back += 1`（绕回处理），元素存入 `array[back]`。
  2. Dequeue（出队）：取出 `array[front]`，`front += 1`（绕回处理）。
- 优势：操作简单；劣势：需处理绕回逻辑，仍可能存在空间浪费（当数组满时需扩容）。

#### （2）链表实现（Queues as Linked Lists）
- 结构设计：
  - 用单链表存储元素，维护两个指针：`front`（队首，链表头部）、`back`（队尾，链表尾部）。
  - 无需处理绕回，动态扩容无压力，是队列的**推荐实现方式**。
- 核心操作：
  1. Enqueue（入队）：新节点插入链表尾部（队尾）。
     - 代码逻辑：
       ```
       Enqueue(Queue: q, Type: value):
         LinkedListNode: node = 新建节点（value）
         IF q.back == null:  // 队列为空
           q.front = node
           q.back = node
         ELSE:
           q.back.next = node  // 尾节点指向新节点
           q.back = node       // 更新队尾指针
       ```
  2. Dequeue（出队）：删除链表头部（队首）节点。
     - 代码逻辑：
       ```
       Dequeue(Queue: q):
         IF q.front == null:  // 队列为空
           return null
         Type: value = q.front.value
         q.front = q.front.next  // 队首指针后移
         IF q.front == null:  // 最后一个元素出队
           q.back = null       // 队尾指针置空
         return value
       ```
- 优势：
  - 入队/出队均为 O(1) 时间复杂度，无空间浪费，无需扩容逻辑。
  - 指针操作简单，无需处理绕回。
- 劣势：需额外存储指针，内存开销略高于数组。


## 四、栈与队列的核心差异对比
| 对比维度         | 栈（Stack）                | 队列（Queue）              |
|------------------|-----------------------------|-----------------------------|
| 检索顺序         | 最新插入的元素先出（LIFO）  | 最早插入的元素先出（FIFO）  |
| 核心操作         | Push（入栈，栈顶）、Pop（出栈，栈顶） | Enqueue（入队，队尾）、Dequeue（出队，队首） |
| 推荐实现         | 数组（简单场景）/链表（动态场景） | 链表（无空间浪费，操作简洁） |
| 关键指针         | 仅需 `top` 指针             | 需 `front` 和 `back` 双指针 |
| 时间复杂度       | Push/Pop：O(1)（数组扩容除外） | Enqueue/Dequeue：O(1)       |
| 典型应用         | 函数调用栈、DFS、回溯算法    | 任务调度、BFS、消息队列      |


## 五、核心应用：搜索算法（DFS vs BFS）
栈和队列的检索顺序直接决定了搜索算法的行为，是二者最核心的实际应用。

### 1. 深度优先搜索（DFS，Depth-First Search）
- 核心逻辑：**沿单一路径深入探索，直到死胡同，再回溯到上一个分支点**，优先处理“最新发现的路径”。
- 数据结构依赖：栈（存储待探索的路径/节点）。
- 示例（咖啡研磨方法研究）：
  1. 从“ Burr 研磨机”（节点 A）出发，发现 3 个待探索节点（B、F、H），全部 Push 入栈。
  2. 取出栈顶节点 B（最新发现），探索 B 时发现节点 C，Push 入栈。
  3. 继续深入探索 C，直到无新节点（死胡同），回溯到栈中前一个节点 F，重复此过程。
- 特点：适合探索“深度优先”的场景（如迷宫求解、拓扑排序），可能错过近路径，但能快速深入细节。

### 2. 广度优先搜索（BFS，Breadth-First Search）
- 核心逻辑：**先探索当前节点的所有相邻路径，再深入下一层**，优先处理“最早发现的路径”。
- 数据结构依赖：队列（存储待探索的路径/节点）。
- 示例（咖啡研磨方法研究）：
  1. 从“ Burr 研磨机”（节点 A）出发，发现 3 个待探索节点（B、F、H），全部 Enqueue 入队。
  2. 取出队首节点 H（最早发现），探索 H 无新节点（死胡同），再取出队首节点 F。
  3. 探索 F 时发现节点 I、G，Enqueue 入队，继续取出队首节点 B，重复此过程。
- 特点：适合探索“广度优先”的场景（如最短路径查找、层级遍历），能优先覆盖所有近路径，避免深度冗余。

### 3. 搜索算法核心差异
| 对比维度         | DFS（栈实现）               | BFS（队列实现）             |
|------------------|-----------------------------|-----------------------------|
| 探索策略         | 深度优先，先深入后回溯      | 广度优先，先覆盖后深入      |
| 待探索节点存储   | 栈（LIFO，优先最新）        | 队列（FIFO，优先最早）      |
| 适用场景         | 迷宫求解、拓扑排序、深度探索 | 最短路径、层级遍历、广度覆盖 |
| 空间复杂度       | 取决于路径深度              | 取决于当前层节点数          |


## 六、核心价值总结
1. **顺序决定行为**：栈和队列的结构相似（均为线性结构，支持插入/删除），但“元素取出顺序”（LIFO/FIFO）的差异，导致算法行为完全不同（DFS vs BFS）。
2. **高效性保障**：核心操作（Push/Pop/Enqueue/Dequeue）均为 O(1) 时间复杂度，仅数组实现的扩容需 O(N) 成本，是高频操作场景的最优选择。
3. **场景适配性**：
   - 需“回溯最新状态”（如函数调用、撤销操作）→ 栈。
   - 需“维持插入顺序”（如任务调度、消息处理）→ 队列。
4. **算法基石**：是 DFS、BFS 等核心算法的基础，后续章节的复杂数据结构（如树、图）的遍历均依赖二者。
