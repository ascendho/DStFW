# 布隆过滤器

## 一、核心定义与本质
### 1. 基础信息
- 发明背景：1970年由计算机科学家Burton Bloom提出，是基于哈希表核心思想扩展的数据结构。
- 核心目标：在**海量键空间**中快速判断“某个键是否已插入”，极致优化内存占用和执行时间。
- 核心特性：
  - 允许**假阳性**（False Positive）：可能误判“未插入的键已存在”，概率非零；
  - 保证**无假阴性**（No False Negative）：绝不会误判“已插入的键不存在”；
  - 本质：一个存储二进制值（0/1）的数组，通过哈希映射标记键的存在状态。

### 2. 核心用途
- 预过滤（Pre-filtering）：访问大型/慢速数据结构（如跨硬盘存储的医疗数据库、海量弱密码列表）前，快速排除“绝对不存在”的情况，避免无效查询开销；
- 快速存在性校验：如校验密码是否在弱密码列表、判断新咖啡是否已尝试过等场景。


## 二、原理演进：从单哈希到多哈希
### 1. 单哈希函数的“指示器哈希表”（局限性）
- 逻辑：用单个哈希函数将键映射到二进制数组索引，插入时设为1，查询时检查索引值。
- 问题：哈希冲突不可避免（大键空间映射到小数组），数组很快被1填满，假阳性率急剧升高，最终失效（如咖啡日志一年后过滤器完全无用）。
- 改进思路：无法根除冲突，需通过“多哈希函数”降低单次冲突导致假阳性的概率。

### 2. 布隆过滤器的核心改进：多独立哈希函数
- 核心设计：使用k个**独立哈希函数**，所有函数将键映射到同一数组的不同索引范围。
- 两大核心操作：
  | 操作   | 逻辑                                                                 |
  |--------|----------------------------------------------------------------------|
  | 插入键 | 对每个哈希函数，计算键对应的数组索引，将所有索引位置的值设为1。       |
  | 查找键 | 对每个哈希函数，计算键对应的数组索引；若**所有索引值均为1**，返回“可能存在”（含假阳性）；若**任一索引值为0**，直接返回“绝对不存在”（无假阴性）。 |

- 优势：假阳性需“k个哈希函数同时冲突”，概率远低于单哈希函数，且保留了无假阴性的可靠性。


## 三、代码实现（伪代码）
### 1. 数据结构定义
```
BloomFilter {
  Integer: size       // 二进制数组长度（m）
  Integer: k          // 哈希函数个数
  Array of bits: bins // 二进制数组（存储0/1）
  Array of hash functions: h // k个独立哈希函数
}
```

### 2. 核心方法
#### （1）插入键（BloomFilterInsertKey）
```
输入：布隆过滤器实例filter、待插入键key
步骤：
1. 初始化循环变量i=0；
2. 遍历k个哈希函数：
   a. 计算当前哈希函数h[i]对key的映射索引；
   b. 将数组bins[index]设为1；
   c. i自增1，直至遍历所有哈希函数。
```

#### （2）查找键（BloomFilterLookup）
```
输入：布隆过滤器实例filter、待查找键key
步骤：
1. 初始化循环变量i=0；
2. 遍历k个哈希函数：
   a. 计算当前哈希函数h[i]对key的映射索引；
   b. 若bins[index] == 0，直接返回“不存在”（无假阴性）；
   c. i自增1，直至遍历所有哈希函数；
3. 所有索引均为1，返回“可能存在”（含假阳性）。
```

### 3. 时间复杂度
- 插入/查找均为O(k)：仅依赖哈希函数个数k，与数组大小m、插入元素数n无关；
- 查找优化：遇0可立即终止，无需遍历所有k个哈希函数。


## 四、参数调优：控制假阳性率
### 1. 假阳性率公式（近似）
\[FalsePositiveRate =\left(1-(1-1 / m)^{n \cdot k}\right)^{k}\]
- 变量说明：n=插入的元素个数，m=数组大小（bin数量），k=哈希函数个数。

### 2. 参数对假阳性率的影响
| 参数 | 变化方向 | 假阳性率变化 | 备注 |
|------|----------|--------------|------|
| 数组大小m | 增大 | 降低 | 更多bin存储信息，冲突概率降低 |
| 插入元素数n | 增大 | 升高 | 更多bin被设为1，误判概率上升 |
| 哈希函数数k | 过多 | 升高 | 每次插入占用更多bin，数组快速填满 |
| 哈希函数数k | 过少 | 升高 | 少量冲突即可导致假阳性 |

### 3. 优化原则
- 需根据具体场景权衡“假阳性率、计算开销（k）、内存开销（m）”；
- 示例（n=100时）：m=1000、k=5时假阳性率仅0.0094，m=200、k=5时假阳性率高达0.6535，可见m和k的合理组合至关重要。


## 五、与哈希表的对比
| 特性                | 布隆过滤器                          | 哈希表（如链地址法）                |
|---------------------|-------------------------------------|-------------------------------------|
| 查找结果            | 概率性（有假阳性，无假阴性）        | 精确性（无假阳性/假阴性）           |
| 内存开销            | 极低（仅存储二进制位，m位= m/8字节）| 较高（需存储键、数据及冲突指针）    |
| 存储内容            | 不存键，仅存存在标记                | 必须存储键及对应数据                |
| 冲突处理            | 无需处理（通过多哈希降低冲突影响）  | 需专门处理（如链地址、开放寻址）    |
| 适用场景            | 预过滤、快速排除不存在项            | 精确查找、键值对存储                |
| 访问速度            | 极快（可放入高速缓存）              | 较快，但受冲突和内存位置影响        |


## 六、核心价值与思想
1. 极致的内存效率：通过“不存储原始键+二进制压缩”，实现海量数据的存在性标记，可放入高速缓存，大幅降低慢速内存访问开销；
2. 权衡思维：接受“可控的假阳性”，换取“无假阴性+低内存+高速访问”，是“准确性-效率”权衡的典型案例；
3. 思想延伸：突破“精确数据结构”的局限，引入“概率性数据结构”，为后续跳表（用随机性优化最坏情况）等结构奠定思路；
4. 技术融合：结合了哈希映射（Chapter 10）和紧凑数据存储（Chapter 12）的核心思想，是数据结构设计中“组合优化”的典范。
